# Interview answer to implementation map

**Clarify first:** device volume (batch limit and payload limit are config), event size, retention (audit and archive retention are Terraform variables), acceptable sync delay ("delayed" after two missed heartbeats, "offline" and alert after `SYNC_OFFLINE_AFTER_S`), conflict requirements (append-only facts never conflict; edits are versioned and reviewed).

**Local log** → append-only, encrypted, durable before the UI confirms; device ID, monotonic `seq`, timestamp, `op_id`, `schema_version` on every event (`web/src/lib/sync`, `src/fieldsync/device.py`, `sdk-ts`).
**Upload** → cursor first, contiguous resumable batches, idempotency key, backoff with jitter (`SyncEngine.syncOnce`, `test_client_resumes_after_lost_acknowledgement`).
**Ingest** → auth, own-device, schema registry, hash recompute, sequence continuity; one transaction; ack through N only after commit (`SyncService.ingest`, `test_ordered_ack_and_projection`, `test_gap_is_rejected_and_reports_expected_sequence`).
**Idempotency** → key + stored result, duplicate suppression, sequence-reuse quarantine (`test_retry_with_same_key_is_idempotent`, `test_resending_acknowledged_events_counts_duplicates_without_duplicating`).
**Compaction** → only after ack; sequence numbers never reused (`test_local_log_is_encrypted_append_only_and_sequence_survives_compaction`, engine and store compaction tests).
**Outbox** → row per event in the commit transaction; idempotent projections; recovery at start-up (`test_outbox_projection_is_idempotent_and_crash_safe`).
**Conflicts** → version checks, review queue, never a silent overwrite (`test_conflicts_are_never_silent_overwrites`).
**Visibility** → local only / uploading / acknowledged / failed in the Field app; fleet connectivity, heartbeat, queue depth, retries, sync lag, rejected schemas, storage; `/metrics`; alert on prolonged offline (`test_fleet_connectivity_lifecycle_and_scan`, `test_metrics_expose_the_signals_operators_need`).
**Security** → least privilege, encryption on device, audit chain, immutable originals (`test_separation_of_duties_and_audited_denials`, `test_immutability_of_events_and_audit`, `test_tampering_with_the_audit_log_is_detected`).
**Failure-mode tests** → lost acknowledgement, dropped request, duplicate, gap, reorder attempt, tamper, unknown schema, crash between commit and projection, audit tamper; a regional outage or storage failure is an infrastructure drill documented in `docs/RUNBOOK.md`, not code.

**Follow-up 1: how do you stop an administrator altering evidence?** No permission path: the admin role cannot read or change events or records and no endpoint mutates them; enrolment needs two different administrators; every attempt, including denials, is audited in a hash chain with signed checkpoints; database triggers block UPDATE and DELETE. Honest limit: a database owner can drop triggers (the test does exactly this) but the chain then fails verification and `/readyz` turns red. True prevention needs WORM/Object Lock storage, `REVOKE` on the tables and a separate audit sink (`deploy/terraform`, documented, not built here).
**Follow-up 2: what if a hash does not match?** Quarantine: store the event exactly as received, never apply it, keep the valid prefix, block the device so ordering is not faked, alert, let a reviewer choose retry or skip with a reason, and record everything in the audit chain (`test_hash_mismatch_quarantines_blocks_and_persists_the_good_prefix`, `test_skip_authorized_advances_cursor_only_for_the_blocked_sequence`). Retry is authorised only when appropriate; the reviewer sees the claimed hash beside one recomputed in their own browser.
