# Security policy

Report vulnerabilities privately to your security team's address (set it here before publishing). Do not open public issues for suspected integrity, audit or access-control flaws. Never include real records, personal data or credentials in reports.

Scope of concern includes: bypassing sequence or hash checks, altering or deleting committed events, defeating the audit chain, cross-device or cross-agency access, and any path where the advisory AI could change or gate data.

Supported version: the latest release. The reference store (SQLite) and bearer-token authentication are development conveniences; see `docs/ARCHITECTURE.md` "Known limits" before any production use.
